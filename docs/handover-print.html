For whoever inherits the guide next year / 15 November 2026 / freefish-campus-guide

Two limits. Scope: 240 nodes, names matched by a word index plus a Levenshtein pass on 5+ letter words within two edits. A room absent from the data is never found, only its nearest neighbour: "restroom" resolved to "restroomgf". No retriever, only data to edit. Contract: the Code node must return exactly three keys (text, kind, ok); Dify compares the count, not the names: our first import died on a four-key answer. We learned that the hard way.

The notch. Booking: the Code node gains a write to the booking API. New failures: a 0.7-confidence match books the wrong room; no state between turns, so a retyped request books twice; the model branch, blind to the graph and restrained only by a prompt, can request a room not in the data. Same input, different outcome.

The condition. The write files a request, not a booking: room ids checked against the data, one idempotency key per user-slot, Estates Office clearing the queue before confirmation. It sits at the credential, above us: the workflow is a DSL file anyone can re-import, so an in-graph guard is one edit away. "Be careful" fails: a wrong booking answers "confirmed".

Evidence for each claim, with file and line, lives in docs/HANDOVER.md in the repository.
